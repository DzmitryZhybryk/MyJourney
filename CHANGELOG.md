# Changelog

<!-- markdownlint-disable-file MD024 -->

Все заметные изменения документируются в этом файле. Формат версий — [SemVer](https://semver.org/lang/ru/).

С июня 2026 фронт и бэк версионируются **раздельно** (одна общая нумерация продукта осталась в истории ниже):

- **Backend** — версия в `backend/pyproject.toml`. SemVer по контракту HTTP-API и машинным кодам ошибок (`code`). Теги `backend-vX.Y.Z`.
- **Frontend** — версия в `frontend/package.json`. Маркер релиза SPA (внешнего контракта нет). Теги `frontend-vX.Y.Z`.

CHANGELOG остаётся один. Новые записи группируются по дате, внутри — под-секции `### Backend X.Y.Z` / `### Frontend X.Y.Z` (а для repo-уровневых изменений — `### Project` без номера версии). Исторические записи ниже — общая продуктовая нумерация до разделения, помеченная областью (`· Backend` / `· Frontend` / `· Project`).

## 2026-11-01

### Backend 7.0.0

- Коды ошибок `invalid_fractional_key` и `component_not_registered` больше не уходят клиенту: оба случая — ошибка в нашем коде, а не ответ на запрос, и теперь отдают общий 500 `internal`. В ответ перестали попадать и их внутренности — ключ порядка в `details` и имя компонента реестра в `message`. Фронт эти коды не отображал; пока прода нет, правило разрешает убрать код (`.claude/rules/python/shared-infrastructure.md`)
- Нарушение собственного допущения кода — отдельная база исключений `InvariantViolationError`, вне дерева ошибок с категорией. Такие сбои пишутся в лог с типом, данными и трейсбеком; раньше middleware логировало их как голый 500 по статусу ответа
- Корень дерева ошибок с категорией переименован в `AppError`: от него наследуются не только ошибки доменов, но и инфраструктурные адаптеры. Тест следит, что у каждой конечной ошибки свой `code` и коды не повторяются — забытый `code` раньше молча уходил клиенту кодом категории

## 2026-10-30

### Backend 6.0.6

- Хранилище файлов для будущего домена `media`: S3-совместимый адаптер на `aiobotocore` в двух бакетах — приватном (оригиналы, браузер кладёт их по подписанной ссылке) и публичном (готовые к показу варианты, анонимное чтение). Сервисы получают отдельные порты `PrivateStoragePort` и `PublicStoragePort`, поэтому сервис загрузки не может подписать ссылку в публичный бакет. API пока не меняется — хранилищем пользуются следующие задачи media
- Подписанная ссылка на загрузку фиксирует тип, точный размер и запрет перезаписи (`If-None-Match: *`): повтор по ней получает 412, а не затирает файл. Подпись всегда SigV4 — иначе для части регионов botocore молча подписывает по SigV2 без этих заголовков
- Сбои хранилища делятся на временные (сеть, таймауты, 5xx, троттлинг) и постоянные (нет прав, нет бакета, неверный запрос) — по ним будущие фоновые задачи решат, повторять ли. Чтение объекта больше заданного предела отвергается по заголовку, не скачивая тело
- Настройки `MEDIA_S3_*` (endpoint и ключи обязательны; регион, имена бакетов, ретраи и таймауты — со значениями по умолчанию, см. `.env.example`). Без них приложение и воркер не стартуют

### Project

- Локальный S3-эмулятор RustFS в дев- (порт 9050) и e2e-стеке (9051) с алиасом `s3.localhost`: подписанная ссылка годится и бэкенду в контейнере, и браузеру. Бакеты, CORS для фронта и анонимное чтение публичного бакета настраивает one-shot `backend/devtools/storage_bootstrap.py` — каталог `devtools` не попадает ни в пакет, ни в прод-образ. **В дев-`.env` нужны `MEDIA_S3_ENDPOINT_URL=http://s3.localhost:9050` и два ключа эмулятора** до `make run` и локального `make test-e2e`
- Integration-тесты поднимают RustFS через testcontainers; unit-тесты адаптера подменяют ответы S3 через `AioStubber`
- Потолок времени теста больше не «никогда не поднимать»: сначала разобрать причину, при объективной — поднимать понемногу, с причиной рядом со значением

### Project

- Compose: общий `ops/docker-compose.base.yaml` и override'ы dev, e2e и prod вместо трёх полных описаний. Прод раскрывается в прежний конфиг
- Дев-стек идёт тем же путём, что прод: `make run` собирает образы (`up -d --build`), гоняет one-shot'ы `myjourney_migrate` и `myjourney_geo_load`, app и worker ждут их. `backend/` монтируется целиком, uvicorn перезапускается только на правках в `app/`. `make watch` пересобирает backend при правке `pyproject.toml` или `uv.lock`

- Таргеты `backend/Makefile` вызывают `uv run` без `--no-sync`: окружение само синхронизируется с lock'ом, в том числе версия проекта после бампа
- CI (`Backend gate`, `Backend integration`) и pre-commit хук запускают uv с `UV_LOCKED`: устаревший `uv.lock` валит гейт, а не перезаписывается молча первым `uv run`. Раньше хук в таком случае коммитил старый lock, оставляя новый в рабочей копии
- e2e-стек берёт код backend из образа, без монтирования. Postgres в деве и e2e закреплён по тому же digest, что в проде

- `CLAUDE.md`: раскладка `.plan/` больше не перечисляется — вместо неё ссылка на skill `backlog`, который её описывает; skill добавлен в список глобальных

После правки этих двух файлов нужна пересборка образа
- `make test-e2e` собирает образы одноразового стека перед подъёмом (`up --build`): раньше локально он брал образы, собранные когда-то прежде, и не замечал изменений в Dockerfile и зависимостях — в CI образов нет, там это не проявлялось
